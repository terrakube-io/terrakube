# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in Terrakube or have security concerns, please report it privately. **Please do not open public GitHub issues for security vulnerabilities.**

You can submit your report through either of the following private channels:

- **GitHub Security Advisory (Preferred):** Create a private vulnerability report at [https://github.com/terrakube-io/terrakube/security/advisories/new](https://github.com/terrakube-io/terrakube/security/advisories/new)
- **Email:** Send details to [security@terrakube.io](mailto:security@terrakube.io)

## What to Include in Your Report

Please include as much of the information listed below as you can to help us better understand and resolve the issue:

- The type of issue (e.g., authentication bypass, privilege escalation, SSRF, SQL injection, or cross-site scripting)
- Affected version(s)
- Impact of the issue, including how an attacker might exploit the issue
- Step-by-step instructions to reproduce the issue
- The location of the affected source code (tag/branch/commit or direct URL)
- Full paths of source file(s) related to the manifestation of the issue
- Configuration required to reproduce the issue
- Log files that are related to this issue (if possible)
- Proof-of-concept or exploit code (if possible)

This information will help us triage your report more quickly.

## Disclosure Policy

We follow coordinated vulnerability disclosure. Please allow the Terrakube maintainers reasonable time to investigate the report, develop a remediation, and publish a fix or advisory before sharing details publicly.
